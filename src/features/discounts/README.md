# 할인·혜택 제보와 검수

할인·혜택 메뉴(`/discounts`)에서 로그인한 사용자가 매장명, 할인 내용·조건, 날짜 범위 또는 상시 여부, 공식 공지 링크를 제출합니다. 제출 직후와 새로고침 후 모두 **내 제보**에서 검수 상태를 확인할 수 있습니다. 접수한 자료의 공식 출처 여부는 검수자가 판단합니다.

| 원본 요구                         | 구현                                                               | 확인 방법                                              |
| --------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------ |
| 6-5 신규 제보, 공식 SNS·공지 링크 | `DiscountsPage.tsx`, `components/ReportForm.tsx`, `api/reports.ts` | `npm run test:account` 안의 discounts-reports 시나리오 |
| 6-2 기간·검수 상태와 본인 조회    | `components/MyReports.tsx`, discount_reports migration             | 제출 직후 pending. 내역은 최신순 20건씩 조회           |
| 6-5 중복 및 권한                  | DB 제약, RLS, 컬럼별 INSERT 권한                                   | `npm run db:test` 안의 discounts_reports.test.sql      |
| 포스터 첨부, 수정·종료 신고, 보상 | 후속 작업                                                          | 별도 단계에서 연결합니다.                              |

공통 인증 migration 다음에 `supabase/migrations/20261123073314_discounts_create_reports.sql`을 적용합니다. 테이블은 사용자 FK로 `profiles(id)`를 참조합니다. 접수 상태와 시각은 DB가 지정하고, 회원은 본인 명의 등록·본인 조회가 가능합니다. 동일 작성자의 매장명·할인 내용·출처·기간이 같은 검수 대기 제보는 중복 저장되지 않습니다. 가입 계정 삭제 시 해당 제보도 삭제됩니다.

로컬 Supabase와 공개 키를 준비하는 순서는 [계정 개발 안내](../auth/README.md)에 있습니다. 기존 개발 DB에서는 `npx supabase migration up --local` 후 앱을 시작하세요. 혜택 제보는 추가 API 키가 필요하지 않습니다. `npm run check`, `npm run db:test`, `npm run test:account`가 각각 입력 검증, DB 권한, 실제 등록 화면을 검사합니다. 기능을 되돌릴 경우 UI 커밋을 revert하고 공유 DB에 접수된 제보는 보존합니다.

## 관리자 검수

관리자 또는 최고 관리자 계정으로 로그인한 뒤 **할인·혜택 → 제보 검수하기**(`/discounts/review`)를 엽니다. 공식 공지를 확인하고 **승인** 또는 **반려 → 사유 입력 → 반려 확정**으로 처리합니다. 대기 목록은 자신의 제보를 제외하고 오래된 순서로 20건씩 표시합니다. 승인된 혜택은 비로그인 방문자도 볼 수 있고, 종료일이 지난 혜택은 한국 날짜 기준으로 공개 목록에서 제외합니다. 반려 결과와 사유는 작성자의 ‘내 제보’에서 확인합니다.

개발 PC에서 테스트하려면 로컬 Supabase에 제보용·검수용 두 계정을 만들고, 로컬 Studio의 Table Editor → user_roles에 **검수용 계정의 UID**와 role `admin`으로 한 행을 추가합니다. 기존 member 행은 유지하세요. 등록 직후 검수 계정에서 페이지를 새로고침합니다. 같은 절차를 자동으로 실행하는 테스트는 `npm run test:account`에 포함되어 있습니다.

| DB 계약                                                      | 동작                                                                                                                                                          |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `review_discount_report(p_report_id, p_decision, p_reason?)` | 서버가 admin/super_admin, 작성자와 검수자의 분리, pending 상태를 확인합니다. approved는 사유 없이, rejected는 공백을 제외한 1~500자 사유로 처리합니다.        |
| `list_published_discounts(p_limit, p_offset)`                | 승인된 기간 미종료·상시 혜택의 매장, 내용, 공식 출처, 기간과 검수 시각을 돌려줍니다. 검수 전 원본과 반려 사유는 비공개입니다.                                 |
| `core_private.discount_review_log`                           | 상태 변경과 같은 트랜잭션에 제보 ID, 검수자, 결정, 시각을 한 번 기록합니다. 감사 기록은 제보 삭제 후에도 보존하며 검수자 탈퇴 시 해당 사용자 참조를 비웁니다. |

제보 등록 migration 다음에 `20261123094548_discounts_review_reports.sql`을 적용합니다. 두 관리자가 같은 건을 처리하면 먼저 저장된 결정이 유지됩니다. 운영 DB 적용 전 백업을 확인하고, 기능 철회 시 RPC 실행 권한과 대기 목록 정책을 먼저 회수한 뒤 화면 변경을 되돌립니다. 이미 접수한 제보와 감사 기록은 보존합니다.

## 공개 혜택 검색

할인·혜택 메뉴에서 매장명이나 할인 내용의 일부를 입력하고 **검색**을 누릅니다. **초기화**하면 조건을 지우고 전체 목록 첫 페이지로 돌아갑니다. 비회원도 사용할 수 있습니다.

- **오늘 이용 가능**은 한국 날짜 기준으로 시작일과 종료일 사이에 있거나 상시인 혜택입니다. 학생증 제시 등 세부 이용 조건은 공지에서 확인합니다.
- **마감 임박**은 오늘부터 6일 뒤까지(총 7일) 종료되는 혜택입니다. 두 조건을 함께 선택하면 오늘 이용 기간에 들어온 마감 임박 혜택만 표시합니다.
- 검색 RPC `search_published_discounts`는 승인된 미종료 혜택의 매장명·설명을 대소문자 구분 없이 부분 일치로 조회합니다. 검색과 날짜 조건을 먼저 적용한 뒤 페이지를 나눕니다. 기존 공개 목록 RPC도 같은 공개 조건을 사용합니다.

제보 검수 migration 다음에 `20261123095813_discounts_search_published.sql`을 적용합니다. `npm run db:test`에서 공개 범위와 날짜 경계를, `npm run test:account`에서 비회원 검색 흐름을 검사합니다.
