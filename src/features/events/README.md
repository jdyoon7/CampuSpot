# 행사·장소 작업 현황

행사 화면은 React/Vite 기반으로 구현했습니다. 현재 공통 인증·학교 계약과 행사 migration이 준비되지 않아 실제 행사 데이터, 관심 저장, 주최자 등록/수정은 연결되지 않았습니다. 미연동 상태에서는 fixture를 서비스 목록에 노출하지 않습니다.

## 요구사항 추적

| 원본 요구사항                              | 상태                                  | 구현 파일                                      | 테스트                 | 외부 설정/의존성                      |
| ------------------------------------------ | ------------------------------------- | ---------------------------------------------- | ---------------------- | ------------------------------------- |
| 행사 목록·상세·학교/일정 필터              | 화면 구현, 실제 데이터 미연동         | `EventsScreen.tsx`, `services/eventService.ts` | 날짜·필터·상태 테스트  | 행사 migration 및 공통 학교 계약 필요 |
| 행사 날짜 입력 검증                        | 구현                                  | `services/eventService.ts`                     | `eventService.test.ts` | 없음                                  |
| 검수 전 비공개 및 미연동/오류/빈 결과 표시 | 공개 경로는 미연동 처리, 상태 UI 구현 | `EventsScreen.tsx`, `types.ts`                 | 검수 필터·상태 테스트  | 서버 검수 권한과 RLS는 미구현         |
| 관심 행사 저장                             | 미연동, 비활성 표시                   | `EventsScreen.tsx`                             | 서비스 미연동 테스트   | 공통 인증 및 저장 API 필요            |
| 장소·동아리·캘린더·제보                    | 예정                                  | 없음                                           | 미실행                 | 별도 단계                             |

## fixture 보존

기존 가상 데이터는 원본 `data/events.ts`를 그대로 두고 `tests/fixtures/events/events.ts`에 복사해 테스트에서만 사용합니다. 두 파일은 복사 시 SHA-256이 일치하는 것을 확인했습니다. 서비스 코드에서는 두 데이터 파일을 import하지 않습니다. fixture는 실제 학교·행사 정보가 아닙니다.

## 공통 기반 요청

- 행사 FK에 사용할 `profiles` 및 학교/캠퍼스 계약, 역할 검증 API가 필요합니다.
- 행사 테이블과 검수 상태를 포함한 B 담당 migration, RLS, 포스터 Storage 정책이 필요합니다.
- 관심 저장에는 공통 사용자 인증 및 북마크/저장 계약이 필요합니다.

계약이 준비되기 전에는 위 기능의 쓰기와 실제 목록 공개를 구현하지 않습니다. Supabase 설정이 있어도 행사 스키마가 없으면 `events_schema_not_ready`로 처리합니다.

## 검증 및 적용

- 단위 테스트: `npm test -- src/features/events/eventService.test.ts`
- 전체 검사: `npm run check` (아직 실행 전)
- DB 테스트: 행사 migration/RLS가 없어 실행하지 않았습니다.
- 변경은 로컬 코드만 포함합니다. DB migration 적용, 외부 서비스 설정, 배포는 하지 않았습니다.

되돌릴 때는 이 PR의 행사 파일 변경만 revert합니다. 기존 WIP fixture 원본과 `.expo/` 파일은 삭제하지 않습니다.
