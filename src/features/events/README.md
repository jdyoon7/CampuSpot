# 행사·장소 작업 현황

행사 화면은 React/Vite 기반입니다. 행사 목록·상세 진입, 학교명·일정·유형 필터, 필터 초기화, 날짜 오류 안내와 상세 조회의 로딩·오류·미연동·미존재 상태를 제공합니다. 공통 인증·학교 기반은 연결됐지만 행사 전용 migration과 RLS가 아직 없어 실제 행사 목록·상세는 미연동입니다. 미연동 상태에서는 fixture를 서비스 목록에 노출하지 않습니다.

## 요구사항 추적

| 행사 목록·상세·학교/일정/유형 필터         | 화면·순수 필터 구현, 실제 데이터 미연동 | `EventsScreen.tsx`, `services/eventService.ts` | 날짜·필터·상태 테스트  | 행사 migration 및 RLS 필요    |

## fixture 보존

기존 가상 데이터는 원본 `data/events.ts`를 그대로 두고 `tests/fixtures/events/events.ts`에 복사해 테스트에서만 사용합니다. 두 파일은 복사 시 SHA-256이 일치하는 것을 확인했습니다. 서비스 코드에서는 두 데이터 파일을 import하지 않습니다. fixture는 실제 학교·행사 정보가 아닙니다.

## 남은 의존성

- 행사 테이블과 검수 상태를 포함한 B 담당 migration, RLS, 포스터 Storage 정책이 필요합니다. FK는 병합된 `profiles` 및 학교/캠퍼스 테이블 계약을 사용합니다.
- 관심 저장에는 공통 사용자 인증 및 북마크/저장 계약이 필요합니다.

계약이 준비되기 전에는 위 기능의 쓰기와 실제 목록 공개를 구현하지 않습니다. Supabase 설정이 있어도 행사 스키마가 없으면 `events_schema_not_ready`로 처리합니다.

## 검증 및 적용

- 단위 테스트: `npm test -- src/features/events/eventService.test.ts`
- 전체 검사: `npm run check` (작업 후 결과 기록)
- DB 테스트: 행사 migration/RLS가 없어 실행하지 않았습니다.
- 변경은 로컬 코드만 포함합니다. DB migration 적용, 외부 서비스 설정, 배포는 하지 않았습니다.

되돌릴 때는 이 PR의 행사 파일 변경만 revert합니다. 기존 WIP fixture 원본과 `.expo/` 파일은 삭제하지 않습니다.
