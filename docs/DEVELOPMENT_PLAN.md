# 개발 순서와 완료 기준

현재 완료: 실행 환경, 역할 분리, 문서, CI 정의, 시작 라우트. 실제 서비스 기능은 미구현.

1. C 공통 기반: 인증/프로필/학교/권한/RLS/Storage. A/B: 설정, 목록/상세 UI, 입력 스키마 및 테스트 준비. 가상 데이터를 서비스 데이터로 노출 금지.
2. 병렬 핵심: A 모임 생성→신청→승인/정원→대결. B 출처 있는 행사 등록→검수→검색/상세→장소. C 실제 할인 제보→검수→만료 검색→혜택 저장.
3. 후속: A 채팅/포인트 공통 연동 및 대결 후기. B 캘린더/행사 홍보/장소 리뷰/동아리/실시간 제보/수집기. C 매장 소유권/쿠폰/포인트/공통 커뮤니티/채팅/알림.
4. 수익화: 공식 Groble 문서 검증→테스트 결제→서버 검증/멱등 웹훅→광고 활성/만료/환불. 실제 지원 없는 부분은 비활성.
5. 출시: 모든 역할의 RLS/동시성/권한/외부 장애/모바일 검증, 운영 정책/백업/복구/관측, PWA와 staging 배포 후 승인받아 production.

각 단계는 화면+실제 DB+권한+성공/실패 테스트+문서+PR까지 끝내야 완료. 키/계정이 없으면 미연동 부분과 독립 작업을 구분하여 진행한다. 전체 27절 요구사항은 docs/PROJECT_SPEC.md 추적표로 각 담당 README에 완료/진행/미연동/예정 상태를 적는다.
