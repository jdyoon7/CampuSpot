# 대학생 여가·교류 통합 플랫폼 개발 프로젝트

## 1. 프로젝트 목표

에브리타임의 대학생 커뮤니티 기능과 KLUE의 사용자 참여형 정보 공유 및 포인트 보상 시스템을 결합한 대학생 전용 여가·교류 플랫폼을 개발한다.

대학생들이 누구와 놀지, 무엇을 할지, 어디서 놀지, 어떤 혜택을 받을 수 있는지를 하나의 서비스에서 해결하도록 한다.

다음 세 가지를 핵심 기능으로 구성한다.

1. 모임
2. 행사 및 장소
3. 할인 및 혜택

세 가지 기능은 독립적인 서비스가 아닌 하나의 통합 플랫폼으로 구현하며, 회원 정보, 데이터베이스, 포인트, 커뮤니티, 채팅, 결제 시스템을 공유한다.

단순한 UI 시연이나 더미 데이터 기반 프로토타입이 아닌 실제 사용자가 가입하고 이용할 수 있는 상용 서비스 수준의 앱을 목표로 한다.

## 2. 기술 스택

- Frontend: React, TypeScript, Vite
- CSS: Tailwind CSS
- Icons: Lucide Icons
- Backend: Supabase
- Database: PostgreSQL
- Authentication: Supabase Auth
- Storage: Supabase Storage
- Realtime: Supabase Realtime
- Serverless Functions: Supabase Edge Functions
- Scheduler: Supabase Cron
- Payment: Groble
- Map: Kakao Maps API
- Public Data: 공공데이터포털 API
- Crawling: Python, BeautifulSoup, Playwright
- AI: Google Gemini API
- Push Notification: Firebase Cloud Messaging
- Error Monitoring: Sentry
- Analytics: PostHog
- Deployment: Vercel
- Version Control: GitHub
- CI/CD: GitHub Actions

모바일 환경을 중심으로 반응형 웹앱을 개발하고 PWA를 지원한다. 추후 Android 및 iOS 네이티브 앱으로 확장할 수 있는 구조로 설계한다.

### 5-2. 실제 행사 데이터 수집

다음 출처를 활용한다.

- 대학교 공식 홈페이지
- 대학교 공식 행사 게시판
- 총학생회 공식 홈페이지
- 학과 및 동아리 공식 홈페이지
- 접근이 허용된 공개 SNS 게시글
- 행사 주최자 제공 정보
- 사용자 제보

공식 API가 있는 경우 API를 우선 사용한다.

공식 API가 없는 경우 이용약관, robots.txt 및 관련 법률을 준수하는 범위에서 크롤링한다.

로그인 제한, CAPTCHA, 접근 제한을 우회하지 않는다.

수집한 행사 정보는 Supabase에 저장한다.

데이터 수집 파이프라인:

1. 원본 데이터 수집
2. 원본 데이터 저장
3. 행사 제목, 일정, 장소 등 정형 데이터 추출
4. Gemini API를 활용한 포스터 및 비정형 텍스트 분석
5. 데이터 유효성 검사
6. 중복 데이터 제거
7. 출처 및 수집 시간 기록
8. 신뢰도 분류
9. 관리자 검수 또는 자동 등록
10. 주기적인 정보 업데이트

AI가 추출하거나 추론한 정보가 실제 출처와 일치하지 않는 경우 자동 공개하지 않는다.

## 11. Groble 결제 시스템 연동

Groble을 서비스의 결제 및 수익화 시스템으로 사용한다.

Groble 공식 개발 문서를 먼저 확인하고 실제 지원되는 API, SDK, 결제 방식, 웹훅, 취소 및 환불 기능을 검토한다.

존재하지 않는 API 엔드포인트나 SDK를 임의로 생성하지 않는다.

### 결제 대상

- 모임 모집글 유료 상단 노출

- 특정 학교 대상 맞춤형 광고
- 기간별 광고 상품

### 결제 처리

- 광고 및 홍보 상품 조회
- 상품 선택
- 주문 생성
- Groble 결제 연동
- 결제 성공 및 실패 처리
- 서버 측 결제 검증
- 웹훅 수신 및 검증
- 결제 내역 저장
- 결제 완료 후 상품 활성화
- 광고 시작 및 종료 시간 설정
- 결제 취소 및 환불 처리
- 중복 결제 처리 방지
- 관리자 결제 관리

결제 금액은 프론트엔드에서 전달받은 값을 그대로 신뢰하지 않고 서버의 상품 정보를 기준으로 검증한다.

결제 완료 리다이렉트만으로 상품을 활성화하지 않는다.

지원되는 공식 서버 검증 방식으로 결제를 확인한 이후 상품을 활성화한다.

웹훅 재전송에 의한 중복 처리를 방지한다.

테스트 결제와 실제 결제 환경을 분리한다.

Groble에서 직접 지원하지 않는 기능은 제한 사항을 문서화하고 지원되는 방식으로 구현하거나 추가 연동 전까지 비활성화한다.

## 26. 필수 개발 원칙

다음 사항을 반드시 준수한다.

1. 기존 Repository가 존재한다면 먼저 현재 파일과 코드를 분석한다.
2. 기존 정상 작동 기능을 무단으로 삭제하거나 변경하지 않는다.
3. 단순한 화면 구현으로 개발을 종료하지 않는다.
4. 모든 버튼과 기능을 실제 백엔드와 연결한다.
5. 실제 서비스 데이터는 Supabase에서 불러온다.
6. 외부 서비스는 공식 개발 문서를 확인한 후 연동한다.
7. 존재하지 않는 API, SDK, 응답 데이터 구조를 임의로 만들어내지 않는다.
8. 실제 행사, 장소, 할인 정보를 사용한다.
9. 가상의 정보를 실제 데이터처럼 표시하지 않는다.
10. 테스트 데이터는 실제 데이터와 완전히 분리한다.
11. 외부 API 키가 필요한 경우 환경변수를 작성하고 필요한 설정을 문서화한다.
12. 외부 연동이 불가능한 기능은 이유를 명시하고 미연동 상태로 표시한다.
13. 데이터베이스 접근 권한을 서버에서 검증한다.
14. 민감한 키를 프론트엔드 및 GitHub에 노출하지 않는다.
15. 팀원이 기능별로 독립적인 개발을 진행할 수 있도록 코드를 모듈화한다.
16. 각 개발 단계가 완료되면 테스트를 실행한다.
17. 오류가 발생하면 원인을 분석하고 해결한다.
18. 모든 중요한 구현 사항과 설정 방법을 README에 기록한다.
19. 유료 서비스 가입, 실제 과금, 운영 데이터 변경, 실제 배포 등은 사용자 승인 없이 실행하지 않는다.
20. 실제로 완료된 기능과 외부 설정이 필요한 기능을 명확하게 구분한다.
